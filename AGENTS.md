# AGENTS.md

## About this project

Website for **Volley Club Nogentais** (a volleyball club), built with the **Hugo** static site framework. The content
itself is French-only, since the site targets a French audience. Deployed at <https://volley-club-nogent.fr/>.

Main content sections (`content/`): club presentation, teams (one per category: U13, U15, U18, regional, departmental,
leisure, beach, etc.), news, registrations, contact, club history.

> Note: site content in `content/` and hardcoded UI strings in templates (e.g. the 404 page, "Latest news" header,
> "Pre-prod" badge) are intentionally in French for the site's visitors — do not translate them. Everything else you
> write or edit (code, comments, docstrings, commit messages, this file) must be in English.

## Structure

- `content/` — Markdown pages and articles (French, `.fr.md` suffix).
- `layouts/` — Hugo templates (partials, shortcodes, per-section layouts).
- `assets/sass`, `assets/js`, `assets/media` — front-end sources (mounted into `static` via `module.mounts` in the Hugo
  config).
- `config/_default/` — Hugo configuration (`config.yaml`, `languages.yaml`, `menus.fr.yaml`, `params.yaml`,
  `sitemap.yaml`).
- `data/calendars/` — match calendars generated by the Python scripts (do not hand-edit, regenerated in CI).
- `scripts/` — standalone Python scripts (not a Hugo module) that fetch and merge match calendars:
  - `ffvb-get-calendars.py` — FFVB calendars (French Volleyball Federation / beach volley).
  - `fsgt-get-calendars.py` — FSGT calendars.
  - `merge-next-games.py` — merges both sources into a single data file consumed by the site.
- `static/admin/` — **Decap CMS** (formerly Netlify CMS) configuration, GitHub backend with editorial workflow (one PR
  per entry). This is the content-editing interface used by non-developers at the club.
- `public/` — Hugo build output, generated, do not hand-edit or commit manual changes to it.

## Dev environment

Local dev goes through Docker Compose (`compose.yaml`), image `hugomods/hugo:non-root`, which runs `hugo server` on port
1313 with `--buildDrafts --buildFuture`.

```bash
docker compose up
```

The site is then served at <http://localhost:1313/>.

If Hugo is installed locally (extended version ≥ 0.99.1 required, see `config/_default/config.yaml`), you can also run
directly:

```bash
hugo server --buildDrafts --buildFuture
```

## Node dependencies

`package.json` only contains devDependencies related to formatting (prettier + go-template/xml plugins) and `bootstrap`
as a CSS dependency.

```bash
npm ci
```

## Python scripts (`scripts/`)

Use a local virtual environment (`scripts/.venv`, gitignored). Lint and format with **ruff** (config in
`scripts/pyproject.toml`, double quotes, 120-char line length, `A,B,D,E,F,ISC,RUF` rule sets, `force-single-line`
imports). `requirements-dev.txt` lists `isort`.

These scripts run in CI (see workflows) to regenerate `data/calendars/` before every build: do not modify the generated
files directly, modify the scripts instead.

## Style and formatting

- **EditorConfig** (`.editorconfig`): LF, 4-space indent by default, **2-space indent** for
  `css,scss,html,json,yaml,md`, 120-char max line length, UTF-8, mandatory final newline.
- **Prettier** (`.prettierrc.json`): no semicolons, single quotes, `arrowParens: avoid`, `proseWrap: always`. `.html`
  files are parsed with `prettier-plugin-go-template` (Hugo/Go templates), `.svg` files with `@prettier/plugin-xml`.
  `.yaml` files are excluded from prettier (`.prettierignore`): they're formatted by **yamlfmt** instead
  (`.yamlfmt.yaml`, 2-space indent, LF).
- **Pre-commit** (`.pre-commit-config.yaml`): standard hooks (trailing-whitespace, end-of-file-fixer, check-yaml/toml,
  files over 4 MB, merge conflicts), `codespell` on `.en.(md|html|toml)` files only, and `prettier` locally via `npx` on
  markdown/html/css/scss/svg.

Before committing, run if possible:

```bash
pre-commit run --all-files
```

## CI/CD (GitHub Actions)

- `10-pre-commit.yaml` — runs pre-commit on every PR and push (`main`, `feat/**`, `fix/**`).
- `98-deploy-preprod.yaml` — builds Hugo (including drafts + future) and deploys to GitHub Pages for `feat/**` and
  `fix/**` branches (preprod/preview).
- `99-deploy-prod.yaml` — on push to `main` **and** every day at 7:15 AM UTC (cron): fetches FFVB/FSGT calendars, merges
  them, builds a minified Hugo site, then deploys via `rsync` to the production VPS (`VPS_DEPLOY_*` secrets). The daily
  cron keeps match calendars up to date even without a new commit.

Both build workflows always run, in this order: fetch FSGT → fetch FFVB → merge → `hugo build`.

## Content editing (Decap CMS)

`static/admin/config.yaml` defines the collections editable through the site's `/admin` UI (GitHub backend, one PR per
edited entry, `multiple_files` i18n structure). Any change to the content structure (new fields, new collections) must
stay consistent with the front matter expected by the templates in `layouts/`.

## Things to watch out for

- The local `.env` file (gitignored) holds a GitHub token used by the Decap CMS backend locally — never commit or log
  it.
- `data/calendars/` and `public/` are generated: any change should go through the source scripts or `hugo build`, not
  direct edits.
- The site is single-language (`fr`) despite the presence of `languages.yaml` and `404.en.html` — check before adding
  any English-language content.
